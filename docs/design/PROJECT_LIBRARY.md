## 1. 目标与边界

| 目标 | 说明 |
|---|---|
| 一句话起步 | 第一次只问一句“你目前研究的课题是什么？”，可只说题目、给开题报告，或直接回车跳过；**不要求填表、不要求写 JSON** |
| 可跳过、不阻塞 | 没有课题时照常精读，相关章节写“通用科研应用价值”（T01） |
| 不编造 | 只说了题目 → 其余字段全部“未定”（T02）；从文件提取的内容在你确认前只是草稿（T03） |
| 版本与快照 | 课题每次修改都形成新版本，旧版保留；每次精读固定一份课题快照，以后课题再改，旧笔记一字不变（T04） |
| 多课题 | 可以有多个课题，但**最多一个默认课题**；本次临时换课题或“不关联课题”不改变默认（T04） |
| 论文事实与课题分离（R7） | 论文客观分析（主笔）**看不到**课题内容；项目视角（Project Lens）在客观分析校验完成后另行生成，只能写 INFERENCE/建议，不能改任何 PAPER 内容 |
| 个人信息不进代码 | 课题名、方案等只存在你的项目库与本机登记里；代码、内置模板、测试、安装包中都不出现任何真实课题名（含 Yang 样稿时用过的临时课题名） |

不在本阶段：中文总览（Stage 8）；用新课题重新整理旧笔记（属于决策 14 的 `rerender`，延后）；课题档案的图形界面（Stage 10）。

## 2. 存放位置与格式

### 2.1 两处存放，各司其职

```
<应用数据目录>/projects/              ← 机器权威记录（唯一的“真”）：与模板登记同一套提交协议
    objects/<sha256>.json            课题版本内容（内容寻址，独占创建，只读）
    sources/<sha256>.txt             导入文件抽出的纯文本（用于来源定位与回放，不含原文件）
    snapshots/<N>.json               登记快照（不可变）：所有课题的版本指针、默认课题、首次提问状态
    CURRENT  journal.log  .lock  quarantine/

<Vault>/科研项目库/                    ← 给你在 Obsidian 里看的可读文件（程序生成；位置见决策 1）
    00-当前科研项目.md                所有课题列表，标出默认课题
    <课题文件夹>/
        课题档案.md                   当前版本，八模块，每条带状态和来源
        当前项目摘要.md               精读时实际发给模型的那段简短摘要（所见即所发）
        来源记录.md                   导入过的文件：文件名、SHA-256、页数/段落数、导入时间
        待确认建议.md                 PENDING（待确认）与 SUGGESTION（研究建议）条目
        历史版本/v001.md v002.md …    每个版本一份只读快照（独占创建，永不改写），末尾附该版本完整数据块
        导入草稿/d001.md …            每次导入生成的草稿与差异（独占创建）
```

**为什么这样分（技术决定）**：
- 机器记录放应用数据目录，复用 Stage 6 已测试的“对象 + 不可变快照 + CURRENT 原子切换 + 审计日志 + 锁 + 受控恢复”代码（抽成共用的 `litreader/store/`），中断、并发、篡改都有现成处理，不需要解析你手写的 Markdown 才能知道“真”值。
- Vault 里的文件满足规范 §2 的目录结构（`00-当前科研项目.md`、`课题档案.md`、`当前项目摘要.md`、`来源记录.md`、`待确认建议.md`、`历史版本/`），你在 Obsidian 里能看、能搜、能随库同步。
- 每份 `历史版本/vNNN.md` 末尾带一个 ```` ```litreader-project ```` 数据块（该版本完整 JSON + SHA-256）。换电脑或应用数据丢失时，`litreader project recover --from-vault` 可从这些文件重建机器记录（逐个校验哈希与版本链，任何一处不符即停止）。

### 2.2 课题文件夹名与课题 ID

- 课题 ID（`project_id`）：创建时生成 `p` + 日期 + 4 位随机十六进制（如 `p20261017-3fa2`），终身不变；笔记 YAML、快照、回执都用它，**不靠题目识别课题**（与论文“不靠中文标题识别”同一原则）。
- 文件夹名：创建时取题目的准确短写（≤ 20 字，过滤 `:/\?*"<>|` 等跨平台不兼容字符，冒号改“——”），重名加“——2”。之后**题目改了也不自动改文件夹名**（避免 Obsidian 里的链接失效）；需要时 `project rename-folder` 显式改名并同步内部链接。

### 2.3 八模块与条目

规范 §6.2 的八模块，每个模块下是固定的条目键（代码内置，显示名为中文；条目键是英文，用户看不到）：

| 模块 | 条目 |
|---|---|
| 01 基本信息 | 正式题目、工作题目、学科、项目状态（构思/开题/实施/结题/暂停）、是否默认 |
| 02 研究背景 | 临床/科研动机、已有证据不足 |
| 03 科学问题 | 核心问题、研究假设、研究目标 |
| 04 对象与设计 | 目标人群、分组、纳入标准、排除标准、研究设计、参考标准 |
| 05 方法与技术 | 实验任务、设备、采集与处理、技术路线 |
| 06 研究指标 | 主要指标、次要指标、探索性指标、操作定义 |
| 07 统计与建模 | 统计方案、特征与模型、验证方案、缺失处理 |
| 08 当前进度 | 已完成、未解决问题、导师意见（用户确认过的） |

每个条目可有多条取值，每条取值保存：

```
value        文字（≤ 600 字）
state        CONFIRMED（已确认）| PENDING（待确认）| UNDECIDED（未定）| SUGGESTION（研究建议）
source       {kind: 用户输入 | 用户编辑 | 文件明确写出 | AI 归纳 ,
              role: 用户确认 | 作者提出（方案作者=你） | 导师建议 | 其他 ,   ← 规范：三种来源不可混称
              file: {name, sha256}?, locator: {page | paragraph | slide}?, quote: 原文逐字片段? }
confirmed_at / updated_at（带时区）, note
```

- 规则（代码强制）：只有你在确认界面明确确认过、或你自己输入/编辑的取值才能是 `CONFIRMED`；**AI 归纳的内容永远不能直接成为 CONFIRMED**（ROADMAP Stage 7 禁止项），最多是 PENDING，经你确认后才变 CONFIRMED，且 `source.kind` 仍记“AI 归纳”。
- 没有任何取值的条目 = `UNDECIDED`，在档案和摘要里显示“未定”。
- `SUGGESTION` 只能出现在 `待确认建议.md`，不进入“当前项目摘要”，不参与项目视角。

### 2.4 当前项目摘要（每次精读发给模型的唯一课题内容）

- 由代码从当前版本生成：只含 `CONFIRMED` 取值，未定/待确认条目只写“〈条目名〉：未定”；不含来源原文、会议纪要、草稿。上限 1 500 字，超出时按模块顺序截断并在摘要末尾注明“另有 N 项已确认内容未纳入”。
- Vault 里的 `当前项目摘要.md` 就是这段文字本身（所见即所发）。

## 3. 课题怎样建立

### 3.1 第一次：只问一句（T01、T02）

时机（决策 2）：Stage 7 安装后的**第一次精读**，在你选好论文之后、运行前估算之前，只问一次：

```
你目前研究的课题是什么？可以只说题目、给出开题报告/研究方案文件的路径，或直接回车跳过（使用通用精读）。
>
```

| 你的回答 | 程序行为 |
|---|---|
| 直接回车 / “跳过” / “没有” | 记下“已问过、已跳过”，**以后不再问**；本次通用精读（T01）。以后可随时 `litreader "新建课题：…"` 或 `project init` |
| 一句话题目（如“〈你的课题题目〉”） | 先确认保存位置（§7），再建最简档案：`01.工作题目 = 你的原话`（CONFIRMED，来源“用户输入”），其余全部 UNDECIDED（T02）；设为默认课题（这是唯一课题）；本次精读即用它 |
| 一个存在的文件路径（.docx/.pdf/.md/.txt/.pptx，可从访达拖进终端） | 进入导入流程（§3.2），确认后继续本次精读；导入中途输入 `q` → 本次改为通用精读，不建课题 |
| 看不懂（既不像题目也不是文件） | 再问一次；第二次仍不明确 → 本次通用精读，下次再问 |

- 题目判定是确定性规则（长度 4–120 字、不是路径、不含“跳过”类词），**不调用模型**、不改写你的原话；正式题目还是工作题目先记为“工作题目”，正式题目 UNDECIDED。
- 不追问学科、样本量、方法等任何其他项（规范 §6.1：不要求填多项表单）。

### 3.2 从开题报告/方案导入（T03）

只读取**你这一次明确给出的那一个文件**（ROADMAP：读取仅用户本次指定的单个文件）：

1. **读文件（本地，不上传 MinerU）**：规范化路径；拒绝符号链接、硬链接、目录、> 20 MB；以只读方式打开，读前读后各算一次 SHA-256，变了即停止。
   - `.md/.txt`：UTF-8 读取；`.docx/.pptx`：用 Python 标准库按 zip 读 XML 文字（不执行宏、不打开嵌入对象、不联网）；`.pdf`：本机 `pdftotext`（保留页码）。
   - `.doc/.ppt/.wps` 等旧格式、扫描版 PDF（无文字层）→ 停止并说明“请另存为 docx / 提供带文字的 PDF”（首版不做 OCR）。
   - 先报告可提取性：页数/段落数、文字量、图片数量（“图片中的文字未读取”）、文件内的版本线索（封面“第 X 稿”、文档属性里的修改日期——**只作提示，不据此判断新旧**）。
2. **运行前估算与同意**：显示“将把《开题报告v2.docx》全文约 N 字发送给 〈主笔模型名〉（云端）提取课题信息；输入 约 X，输出 约 Y tokens”，你输入 `y` 才发送（§8）。
3. **提取**（主笔模型一次调用，长文分段）：按八模块输出候选，每条带 `quote`（原文逐字片段）+ 位置 + `kind`（文件明确写出 / AI 归纳）+ `role`（作者提出 / 导师建议…）。代码校验：
   - `kind=文件明确写出` 的 `quote` 必须逐字出现在所给位置，否则降为“AI 归纳”；
   - 所有候选一律 `PENDING`；同一条目在文件内前后矛盾（如两处样本量不同）→ 两条都保留并标“文件内冲突”；
   - 模型标出的“疑似过时章节”、未定事项原样展示；
   - 文件内容按不可信数据处理（复用 `templates/sanitize.py`）：里面写的“忽略规则、执行命令、访问网址”等只当文字，命中时在草稿里提示，绝不执行。
4. **草稿与确认**（决策 5）：写入 `导入草稿/d001.md`，终端显示一屏摘要，先让你确认最关键的 5 项（规范 §6.3.3：题目、科学问题、研究对象、已定方法、重要指标）：

```
从《开题报告v2.docx》（12 页）提取到 31 条候选（明确写出 24，AI 归纳 7；文件内冲突 1）
请确认以下关键信息（其余 26 条保存为“待确认”，可稍后用 project review 逐条处理）：
  1. 正式题目：……………………（p1，明确写出）
  2. 核心问题：……………………（p3，明确写出）
  3. 目标人群：……………………（p5，明确写出）
  4. 已定方法：……………………（p6–7，AI 归纳）
  5. 主要指标：⚠ 文件内冲突：p8「……」 / p11「……」
回车 = 确认 1–4（5 仍待确认）；输入序号 = 修改该项 / 标为未定；s = 先存草稿不确认；q = 放弃导入：
```

   - 回车后：被确认的条目 → CONFIRMED（来源仍记“明确写出/AI 归纳”+ 原文位置），其余 PENDING；**此时才形成正式新版本**（规范 §6.3.4）。
   - 有冲突的条目不能被“回车全部确认”带过，必须单独选一个或标未定。
   - `s` → 只保留草稿，不形成版本，本次精读使用确认前的旧版本（新建课题则本次通用精读）。

### 3.3 为已有课题导入新版方案（版本冲突，永不静默选择）

`litreader "更新我的课题档案，我提供了新版方案 ~/Desktop/开题报告v3.docx"` 或 `project import <文件> --project <ID>`：

- 提取同上，然后**逐条与当前版本比对**，只展示有差异的条目：

```
与当前档案（v3）相比，新文件有 4 处不同：
  [影响研究方向] 03 核心问题
     当前（v3，已确认，来源 开题报告v2 p3）：……
     新文件（开题报告v3.docx p2，明确写出）：……
     1 保留当前 / 2 改用新文件 / 3 标为未定：
  06 主要指标  当前：……  新文件：……   1/2/3：
  …
其余 2 处（非核心）：回车 = 全部改用新文件 / n = 全部保留当前 / 序号 = 逐条处理：
```

- 01 题目、03 科学问题、04 对象与设计（“影响研究方向/核心方案”）必须逐条明确选择；其余可批量处理（规范 §6.4）。
- **不因为文件更新、文件名带 v3、修改日期较新就默认采用新文件**（规范 §6.3.5、ROADMAP 停止条件）。若新旧两份文件的版本关系无法判断（例如两份都是 v2、内容互有增删），先问“这两份哪一份是你现在的方案？”，你回答前不形成新版本。
- 新文件里有而当前档案为“未定”的条目 → 作为 PENDING 加入，同样需确认才成 CONFIRMED。

### 3.4 手动修改

三种方式，结果都是“展示差异 → 你确认 → 新版本”：

1. **一句话**：`litreader "把课题的主要指标改为步速和双任务成本"` → 规则先找条目名；规则不确定时经你同意才用模型解析，且模型给出的新值必须逐字来自你的原话（与 Stage 4/5 意图解析同一规则）。来源记“用户输入”，直接 CONFIRMED。
2. **命令**：`project set <条目> "<值>"`、`project undecide <条目>`、`project review`（逐条处理待确认）。
3. **在 Obsidian 里直接改 `课题档案.md`**：程序记得自己上次写出的文件哈希。下次运行发现文件被改过：
   - 每个条目在文件里是固定格式的一行（`- **核心问题**〔已确认〕：……〔来源：……〕`），程序只解析这种行，把改动列成差异让你确认；确认 → 新版本（来源“用户编辑”），并把你改过的那份文件先原样存入 `历史版本/手动编辑-<时间>.md` 再重新生成；
   - 无法识别的改动（删了格式、写了大段新文字）→ 列出“未能识别，未采用”，**不覆盖你的文件**，本次仍用上一个已确认版本，并提示用 `project set` 或一句话修改；
   - 你拒绝 → 你的文件保持原样，程序用已确认版本，每次运行提醒一次，直到 `project sync` 处理。

## 4. 快照与每次精读固定版本（T04）

1. 精读开始时解析本次课题：一句话里“本次不关联课题” → 无；“用〈课题〉角度 / 关联〈课题〉” → 该课题（只本次，不改默认）；否则 → 默认课题；没有默认但有多个课题 → 问一次（§6）；一个都没有 → 无。
2. **冻结**：与模板一起冻结（规范 §5.4 第三关“一个当前项目快照”）：`ProjectSnapshot = {project_id, version, sha256(该版本对象), summary_sha256(当前项目摘要文字), registry_snapshot: N}`。本次运行全程只用内存中的这份字节；运行中你改了课题档案，本次不受影响。
3. **写入**：笔记 YAML（现有字段 `project_id / project_version / project_relation`，新增 `project_snapshot_sha256`）、证据档案 JSON 的 `project` 段（含当时的摘要全文，便于以后核查“当时依据的是哪版课题”）、回执。
4. 课题以后更新、切换默认、改名、归档：**旧笔记与旧证据档案一字不变**（它们本来就是独占创建；测试再比对文件哈希）。`project show <ID>@<版本>` 随时可看当时那一版。

## 5. 笔记中“对课题的价值”怎样生成（Project Lens，R7）

### 5.1 单向依赖

```
客观分析（主笔，看不到课题）→ 校验闸门 → AnalysisRecord（冻结，记哈希）
                                               ↓ 只读
                       冻结的项目快照 → Project Lens（另一次模型调用）→ Lens 校验 → 只写 Lens 块
```

- **主笔提示中不含任何课题内容**（测试断言）：同一篇论文，不同用户、不同课题，客观部分（论文事实、PAPER 条目、表格、图表解读）完全相同（规范 §6.6 末句）。
- Lens 输入 = 当前项目摘要 + 已通过校验的客观分析条目（每条带编号与 basis_block_ids），不再读原文全文，不能新增论文事实。
- Lens 结束后再算一次 AnalysisRecord 哈希，必须与之前相同（测试断言“Lens 不回写 AnalysisRecord”）。

### 5.2 Lens 输出（规范 §6.6 五项 + 关联矩阵）

| 输出 | 规则 |
|---|---|
| 1 相关程度 | 高 / 中 / 低 / 无直接关联 + 具体理由（INFERENCE）；理由必须引用至少一条客观分析条目编号；**不得以题名相似度为依据**（提示明令 + 理由里只出现“题名相似”类措辞时降为“低”并告警） |
| 2 可支持课题的环节 | 背景/问题/对象/范式/指标/建模/讨论 中的若干项，每项引用客观条目编号 → 由代码生成回跳原页的链接 |
| 3 可借鉴的方法 | 方法 + 适用前提 + 课题中尚未满足/未定的前提 |
| 4 不能照搬的 | 结论、目标人群、设备、结局定义、验证限制 |
| 5 下一步建议 | ≤ 3 项，每项以“建议：”开头；**不改变课题档案**（决策 6） |
| 关联矩阵 | `维度｜本篇已证实内容｜当前项目已确认情况｜借鉴/差异｜原页证据/状态` |

### 5.3 代码强制的 R7 闸门

1. Lens 的每条文字只能是 INFERENCE 或“建议”；出现 PAPER 标签 → 拒绝该条。
2. 矩阵里“本篇已证实内容”一列**由代码按条目编号从 AnalysisRecord 原样复制**（模型只给编号），“当前项目已确认情况”一列**由代码按条目键从快照复制**；模型只写“借鉴/差异”。因此 Lens 无法改写论文事实，也无法改写课题内容。
3. 课题中“未定”的条目，矩阵里由代码写“未定（论文做法仅供参考，不代表已采用）”；Lens 文字若把论文作者的方法说成“本课题采用/已确定” → 措辞闸门拒绝（复用 Stage 3 措辞判官的规则式部分）。
4. Lens 文字里出现的数字必须见于所引用的客观条目或课题摘要，否则拒绝该条（防止新造数字）。
5. Lens 调用失败或全部条目被拒 → 照常出笔记，该块改为“通用科研应用价值”（来自客观分析里原有的通用价值），YAML `project_relation: LENS_FAILED`，终端提示；不阻塞、不重试付费调用超过模型链的正常降级。

### 5.4 在笔记里的位置

- **没有课题（或本次不关联）**：笔记与现在**逐字节相同**（`main.general` 的 Zhong golden 继续作为回归测试）。
- **有课题**：
  - 首层“三分钟了解论文”：原“通用科研价值（INFERENCE，未关联课题）”一行保留，下方加一行“**当前课题价值（INFERENCE，课题 v3）：** 相关程度 + 一句理由”（规范 §3.2 第 3 项）。
  - `main.general`（十章）：放在“八、本篇论文最值得借鉴的3件事”中，3 件事之后新增 `### 与当前课题的关联（INFERENCE，课题《…》v3）`，内含五项与矩阵（决策 4）；8 节标题与 3 件事本身不变（3 件事是客观分析的一部分，不因课题而变）。
  - `main.spec_appendix_a`（九章）：放在“七、与当前科研项目的关系／通用科研价值”。
  - 用户模板：新增块类型 `project_lens`；模板没放这个块而本次有课题 → 闸门自动补在含 `borrow_items` 的章节末尾（没有则在 UNKNOWN 章节前），并告警。
  - 批注保护区里的“对课题方案的具体决定”保持空白，永远由你填写。
- YAML `project_relation`：`高 / 中 / 低 / 无直接关联 / 无关联课题 / LENS_FAILED`。

## 6. 多课题

- `project list` 显示所有课题（ID、文件夹、题目、版本、状态、是否默认）。**默认课题最多一个**，存在登记快照的 `prefs.default_project` 里（个人课题名只出现在快照与你的 Vault 中，不进代码或 `config.example.toml`）。
- `project switch <课题>`（或“把默认课题切换为…”）：改默认 = 新登记快照，旧默认课题档案不动（规范 §6.4）。
- 本次临时使用另一课题、本次不关联：只影响本次冻结，不改默认（T04）。
- 没有默认、却有多个课题时（例如你把默认课题归档了），精读时问一次：

```
本次关联哪个课题？ 1. 〈题目A〉  2. 〈题目B〉  0. 不关联（通用精读）
输入序号（加 * 同时设为默认，如 1*）：
```

  不根据论文内容自动挑课题（规范 §11：多个而不可消歧时问一次；§6.6：不硬凑关联）。
- `project archive <课题>`：标为归档，不能再被选为默认/本次课题，文件全部保留；`project unarchive` 恢复。不提供删除命令（要删就在访达里删 Vault 文件夹 + `project forget`，后者只在登记里标记 REMOVED）。
- 课题名只按 ID、文件夹名或题目的**唯一前缀**匹配；匹配到多个 → 列出让你选。

## 8. 隐私：课题内容发给模型时要说清楚

| 何时发送 | 发什么 | 发给谁 | 怎样同意 |
|---|---|---|---|
| 导入开题报告 | 你选定文件的**全文**文字（不含图片） | 主笔模型（主用，失败按备用顺序） | 导入时单独估算 + `y`（每次导入都问） |
| 每次精读（有课题时） | 当前项目摘要（≤ 1 500 字，仅已确认内容）+ 客观分析条目 | 主笔模型 | 写在运行前估算里，随那次 `y` 一起同意（决策 3） |
| 一句话修改课题（规则不懂时） | 你那句话 | 交叉核对模型 | 先问“要让模型帮忙理解吗？” |

运行前估算新增一行（示例）：

```
  项目视角（DeepSeek deepseek-flash）：将发送课题《……》v3 摘要（约 620 字，已确认 9 项）＋本篇分析要点；输入 约 9,800，输出 约 1,500 tokens（未实测，估算）
```

- 估算比例：Lens 输入 ≈ 主笔输出 × 1.0 + 摘要字数 × 0.7 + 1 500，输出 ≈ 1 500（首次真实调用后校准）；导入：≈ 文件字数 × 0.6 + 2 000 / 输出 ≈ 3 000。
- 回执记录“本次发给模型的课题内容”的 SHA-256 与字数（不存全文；全文在证据档案的 `project` 段，只在你本机）。
- 课题内容不会发给 MinerU、看图模型或任何其他服务。

## 9. 与模板库的接口（规范 §5.4 第二关第 3 级）

- 选择优先级保持 Stage 6 的顺序：0 本次指定 → 1 该论文类型首选 → 2 与研究设计匹配的专用主模板 → **3 与当前课题兼容的专用主模板** → 4 默认主模板 → 5 通用。
- “与当前课题兼容”的定义（技术决定）：**只看你明确的关联**——`litreader templates prefer <模板> --project <课题>`（或一句话“这个课题用〈模板〉”）把模板 ID 记在登记快照 `prefs.prefer_for_project[<project_id>]` 里；不按模板的主题标签与课题题目做文字相似度匹配（规范：不按题名相似度硬凑）。该模板仍须通过资格过滤（ACTIVE、主模板、论文类型适用）。
- 第 3 级用的是**本次冻结的课题**（临时课题就用临时课题的偏好；本次不关联 → 第 3 级为空）。
- 模板选择理由显示示例：`理由：课题《……》指定的主模板（没有适用于横断面研究的专用主模板）`。
- 模板仍然看不到课题内容；`TEMPLATE_DATA` 不含课题信息。
